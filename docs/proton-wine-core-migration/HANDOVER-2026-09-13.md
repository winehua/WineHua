## 4. 当前架构

```
┌─ HAP 进程（ArkTS / NAPI）  app.hackeris.winehua ────────────────────────────┐
│  WL_Server(Wayland 合成器) │ WL_AUDIO(AudioBroker IPC server) │ WL_Broker(NCP 拉起子进程) │
│  ★ OHOS 不能 fork/exec：所有 wine 子进程经 Process Broker + NCP AppSpawn 拉起 │
└───────────────────────────────┬────────────────────────────────────────────┘
                                │ fd 传递（wineserver_sock / wine_audio_bootstrap / graphics socket）
┌─ Wine 子进程（每进程一个 libwine_childNN.so）───────────────────────────────┐
│  loader(ntdll.so) → wine server 客户端 → PE 应用                                │
│  翻译器：HODLL  = libwow64fex.dll   (32 位 / wow64)                            │
│          HODLL64= libarm64ecfex.dll (64 位 / arm64ec)                          │
│  图形：win32u(WGL/EGL) → winewayland.drv(.so) → HAP WL_Server                  │
│        Vulkan: winevulkan → venus ICD → virglrenderer(宿主) → GPU               │
│        D3D: DXVK(legacy 1.10.3 / modern 2.6) 或 wined3d                        │
│  音频：mmdevapi → wineohos.drv → AudioBroker(HAP) → OHOS AudioRenderer          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 Wine 侧 OHOS 平台层落点（改代码时看这些文件）

| 模块 | 文件 | 作用 |
| --- | --- | --- |

| 文件系统 | `ohos_file.{c,h}`、`unix/file.c`、`mountmgr.sys/unixlib.c` | OHOS 无 `symlink()`：dosdevices 四条回退、盘符枚举 |

| 探针 | `programs/winehua_{graphics,audio,d3d11,vulkan,dinput}_smoke`、`winehua_keep` | 真机诊断；`winehua_keep` 桌面保活 |

### 5.2 已经修掉并真机验证的根因（**不要回退**）

1. **`could not exec the wine loader`** → Valve 树缺 OHOS loader 守卫，随平台层重放修复。
2. **wineboot 50ms 消失** → `virtual.c` 的 `kernel_writewatch_init()` 调 `userfaultfd`，沙箱 SIGSYS。
   修法：`USE_UFFD_WRITEWATCH` 定义处加 `!defined(__OHOS__)`。
3. **wineserver 13ms 被杀** → `server/fsync.c` 无条件探测 `futex_waitv`(449)。修法：仅显式设 `WINEFSYNC` 时才探测；
   `dlls/ntdll/unix/fsync.c` 同款守卫。（定位手法：`server/main.c` 的 `sigsys_diag()` 把 syscall 号写进 prefix）
4. **卡在 "Wine Mono 安装器"** → 改成 `BUILD_WINE_MONO=0`（产品本来就不带 mono）。
5. **OHOS unixlib 入口 index 错位** → `unix_ohos_set_wowbox64_fault` 必须放回 **index 8**（预编译 `wowbox64.dll` 的 ABI）。
6. **SMC 双翻译器冲突（重大）** → 32 位默认改 FEX（`HODLL=libwow64fex.dll`，可用 `WINEHUA_WOW64_ENGINE=box` 回退）；
   `ohos_virtual.c` 里不是自己的故障 `return 0` 交还 sigchain；按 `/proc/self/maps` 探测翻译器。
   结果：`result=epilog` 284,684 次 → **0**，进程日志 572k → 2.2k 行。
7. **EGL 门** → Valve 的 `win32u/opengl.c` 用 `WINE_USE_EGL` 门控（app 从不设）。改为 `WINEHUA_EGL_LIBRARY_PATH` 存在即启用。
8. **`SetPixelFormat` 空指针崩溃（今天修掉）** → 11.0 的 `p_surface_create` 比 11.10 多一个 `BOOL raw`；
   `dlls/winewayland.drv/{opengl_readback.c,h,vulkan.c}` 补签名后 core 套件 PASS。
   **教训**：复用的产品预编译件是按主库 11.10 头文件编的，凡"函数指针 entry"在 11.10/11.0 之间有签名差异的必须逐一对齐
   （排查：`grep -iE 'incompatible.*function pointer' build/*.log`）。

## 6. 剩余问题（按优先级）

### 6.1 音频：未处理页错误（最高优先，当前 0/2）

**现象**：`audio-x64` / `audio-x86` 都失败，子进程 `exit=5`（= `0xC0000005` 未处理页错误）。

**现场证据**（wine 子进程 stderr 日志，见 §7.4）：
```text
trace:mmdevapi:AudioClient_Create ...        ← 反复循环
trace:mmdevapi:client_GetMixFormat ...
trace:mmdevapi:client_Release / client_Stop
trace:mmdevapi:MMDevice_SetPropValue ...
[SMC] translator probe: fex=0 box64=0
[SMC] enter tid=2173 sig=11 addr=0x115cb252 pc_in=0x6fffeaa5c4 teb=0x1f0000 fn=0
[SMC] tid=2173 sig=11 addr=0x115cb252 pc_in=0x6fffeaa5c4 prot=--- dynarec=0 result=continue-chain wine=1
```
**已知事实**：
- AudioBroker 本身**正常**：冷启动日志有 `[AudioBroker] renderer ready rate=48000 ch=2 callbackFrames=960`、
  `[AudioBroker] bootstrap accepted conn=1 pid=<child>`；子进程拿到 `[WineChild] AUDIO fd=512`。
- 崩溃发生在 mmdevapi 与 OHOS 后端交互过程中，`prot=---` 说明**故障地址不在 Wine 任何 view 里**（不是保护页语义）。
- `pc_in` 落在 `0x6fff…` 高区（另一处 32 位进程的同类日志是 `0x7ff5…`），**尚未确定属于哪个模块**。

**下一步（建议顺序）**：
1. 打开 `WINEHUA_DUMP_PHDR=1` 让 ntdll 打印 unix 模块区间，把 `pc_in=0x6fffeaa5c4` 归位到具体模块（wineohos.so / winewayland.so / winevulkan.so / 翻译器 code cache）。
2. 用 `WINEDEBUG=+ohosaudio,+mmdevapi` 抓完整调用序列，确认是"设备枚举循环"还是 `IAudioClient::Initialize` 内部。
3. 检查 `dlls/wineohos.drv/ohos_audio_client.c` 的 bootstrap 握手（`parse_env_fd("WINE_OHOS_AUDIO_BOOTSTRAP_FD")`）与 `entry/src/main/cpp/audio/audio_broker.cpp` 的协议版本是否一致。
4. 注意 32/64 都失败且 x86 现在跑 FEX ⇒ **与翻译器无关**，更像 IPC/后端契约问题。

### 6.2 DXVK：present 失败 + 部分子测试全 0

**现象**：`dxvk-legacy-x64.json` 里 `presentResult = -2147467259`（`0x80004005`）、`presentFrames=0`；
`heavenPassMatrix`（mrtGbuffer / d24ReadonlyShadow / rgba16fRtvSrvLoad / miniPipeline）与 `comparisonSampler` 返回全 0；
用例最后停在 `"message": "D24S8 cube-array pending"`，被 runner 判超时。

**已确认不是"渲染完全不可用"**：`featureLevel=11.0`、纹理/采样/计算/子资源/深度模板矩阵大量通过。

**下一步**：先查 present 路径（`0x80004005` 通常来自 Vulkan/swapchain 调用失败，对应 `win32u/vulkan.c` 的
`win32u_vkGetSwapchainImagesKHR` / `winevulkan` / venus 的 surface-queue 通道），再看 Heaven 小管线为什么全 0。

### 6.3 未覆盖的套件

`wine-vulkan`、`wine-vulkan-present`、`d3d8`、`d3d9`、`d3d12`、`gpu-diagnostics`、`dxvk-modern-*` 都**还没跑**。
这些是 M3 Gate 的内容（见 `build-risk-map.md` §5）。网络/TLS/多进程 IPC 的 Gate 用例**目前还没有**，需要补。

### 6.4 内存操作的两条待决项（用户明确要求"参考原实现逻辑"）

详见 `w1-memory-op-parity-2026-09-13.md`，摘要：
1. **WoW64 Vulkan 别名**：移植树现在是"写一个字节探测别名是否共享页"，对设备内存（dma-buf/Venus BO）有副作用风险；
   主库工作区已改成 `dlls/win32u/winehua_shared_map.h`（优先 dup 活 BO fd、`map_files` 兜底、**不做写探测**）。
   **建议：等主库落地后整段同步，不要自己另造一套。**
2. **`server/mapping.c`**：移植树无条件调用探测版 `free_available_high_map_addr()`；主库用 `#ifdef __aarch64__` 分支
   （非 aarch64 走原版 `free_map_addr()`）。arm64 目标上等价，建议补 `#ifdef` 对齐以免以后踩坑。

## 7. 怎么编译 / 打包 / 装机 / 测试（可复跑）

### 7.1 编译（容器内，工作目录 = 仓库根 `/data/src/winehua`）

```bash
# 1) Wine（全量或增量）
WINE_SRC=/data/src/winehua/thirdparty/wine-valve bash scripts/w1-m4-build-merged.sh
# 2) 组装运行时（wine-data.zip + suite 定义），不带 mono
BUILD_WINE_MONO=0 bash scripts/w1-m2-assemble.sh
# 3) 打 HAP
bash scripts/w1-m3-build-hap.sh
```

产物：`entry/build/default/outputs/default/entry-default-signed.hap`（约 314 MB）。
Wine 编译日志：`build/w1-m4-merged-build.log`；assemble/HAP 日志在容器 `/tmp/w1-*.log`。

**增量判断**：改 `dlls/*.c` 后只需 step 1+2+3；只改 HAP 侧（`entry/src/main/cpp|ets`）只需 step 3。
**检查修复是否进包**：比对源码 mtime 与构建产物 mtime，并确认符号确实在产物里：
```bash
ls -l --time-style=long-iso thirdparty/wine-valve/dlls/winewayland.drv/opengl_readback.c
ls -l --time-style=long-iso build/wine-ohos-aarch64/dlls/winewayland.drv/winewayland.so
strings build/wine-ohos-aarch64/dlls/winewayland.drv/winewayland.so | grep winehua_readback_surface_create
```
> ⚠️ 本次踩过的坑：PE 变体 `aarch64-windows/winewayland.drv` 只有一个 `dllmain.o`，
> **真正的驱动代码在 `winewayland.so`（unix 侧）**，改 `opengl*.c`/`vulkan.c` 后要看 `.so` 的时间戳。

### 7.3 跑测试

```powershell

& $hdc shell "aa start -a EntryAbility -b app.hackeris.winehua"
# 等桌面起来后，跑某个 suite
& $hdc shell "aa start -a EntryAbility -b app.hackeris.winehua --ps winehua.mode smoke --ps winehua.suite core --ps winehua.run_id core-<id> --ps winehua.prefix reuse"
```

可用 suite（定义在 `scripts/assemble.sh` 生成的 `smoke/suites.json`）：
`core` `opengl` `audio` `d3d8` `d3d9` `wine-vulkan` `wine-vulkan-present` `dxvk` `dxvk-dynamic`
`dxvk-long` `dxvk-modern-baseline` `dxvk-modern-long` `gpu-diagnostics` `dxvk26-requirements` `d3d12` `all` `long`

请求键：`winehua.mode=smoke` / `winehua.suite` / `winehua.run_id` / `winehua.prefix=reuse|clean` / `winehua.long_seconds`。

### 7.4 取结果与日志

```powershell
$base = '/data/app/el2/100/base/app.hackeris.winehua/files/.wine/drive_c/smoke/results'
& $hdc shell "cat $base/<runId>/suite-summary.json"
& $hdc shell "cat $base/<runId>/<testId>.json"          # 单用例详情+metrics
# wine 子进程 stderr（最重要，WINEDEBUG 输出都在这）
$hdc file recv "/data/app/el2/100/base/app.hackeris.winehua/temp/wine_stderr_$(Get-Date -Format yyyyMMdd).log" .
```

**注意事项**
- 抓 hilog 前先 `hilog -r` 清缓冲，否则关键行会被冲掉（实测 60 秒内就会轮转）。
- `aa start` 在 App **已存活**时走 `onNewWant`（引擎必然已就绪，直接跑测）；
  要复现"冷启动初始化"必须 `aa force-stop` 后再 `aa start`（实测 force-stop 后会重新拉起 AudioBroker/prefix）。
  引擎处于坏状态时，**重装**是最可靠的自愈手段。
- 单用例超时很长（dxvk 系列 `timeoutMs=180000`），整套 dxvk 要跑十几分钟。
