# 决策记录 0004：各形态的默认显示模式

> 决策日期：2026-09-10（平板默认虚拟桌面）、2026-09-12（开鸿设备统一虚拟桌面）
> 决策结论：**按设备形态给默认值**——平板默认虚拟桌面（用户可切换），PC / 2in1 默认多窗口，手机与开鸿设备固定虚拟桌面。
> 最后核实：2026-09-24
> 相关文档：[../architecture/compositor.md](../architecture/compositor.md)（三种显示形态）、[../architecture/platform-ohos.md](../architecture/platform-ohos.md)（形态判断）

## 一、两种模式

| 模式 | 画面怎么呈现 | 窗口怎么管 |
|---|---|---|
| **虚拟桌面**（virtual） | 所有 Wine 窗口合成到一个全屏画面里，看起来像一台完整的电脑桌面 | 合成器自己按坐标找目标窗口 |
| **多窗口 / 融合**（fusion） | 每个 Wine 窗口对应一个独立的系统窗口 | 交给系统的窗口管理器（层级、装饰、任务切换） |

两种模式没有优劣之分，取决于设备的操作方式。

## 二、各形态的默认值

| 形态 | 默认模式 | 用户能改吗 |
|---|---|---|
| 平板（`tablet`） | **虚拟桌面** | 能（设置里切换） |
| PC / 2in1 | **多窗口** | 能 |
| 手机（`phone`） | **虚拟桌面** | 不能，固定 |
| 开鸿设备 | **虚拟桌面** | 不能，切换入口已移除 |

## 三、平板为什么默认虚拟桌面

**理由：操作更方便。**（2026-09-10 的约定）

平板是触摸操作，多数时候没有鼠标键盘。这两种模式在平板上的实际差别是：

- **虚拟桌面**：所有内容在一个画面里。触摸或触控板操作时只需要面对一个面，Windows 程序里的按钮、菜单都在同一个坐标系里，点哪儿是哪儿。
- **多窗口**：每个 Windows 窗口变成独立的系统窗口。系统那套自由窗口管理（拖拽、改大小、层叠）在触摸屏上本来就不好用，而程序内部的小控件还是要精确点到——多出来的那一层窗口管理帮不上忙，反而把画面切碎了。

PC / 2in1 的情况正相反：屏幕大、有鼠标，多窗口是 PC 上的正常用法，所以那边默认多窗口。

另外，这个默认值也**沿用了各形态既有的体验**——老用户升级上来，看到的和以前一样，只有自己在设置里切过才会变。

## 四、开鸿设备为什么固定虚拟桌面

2026-09-12 实测：开鸿 PC 上 `createSubWindowWithOptions` 返回 1300002，**系统不支持子窗口**。

多窗口模式下，Wine 的弹出菜单、提示框、模态对话框都靠子窗口承载——不支持子窗口，这些全都弹不出来（Wine 菜单点了没反应就是这个原因）。

处理：**开鸿设备统一用虚拟桌面，并把设置里的模式切换入口去掉**。不给出一个切过去就坏掉的选项。

将来要恢复多窗口，得先确认系统的子窗口能力可用，或者改成由原生层自己合成弹窗（后者是另一条路，见 [../architecture/compositor.md](../architecture/compositor.md) 里多窗口模式的承载方式）。

## 五、写在哪儿

| 位置 | 内容 |
|---|---|
| `entry/src/main/ets/service/DesktopModeService.ets:13` | 默认值：`deviceType === 'tablet' ? MODE_VIRTUAL : MODE_FUSION` |
| `entry/src/main/ets/service/WineWindowManager.ets` 的 `applyModePolicy()` | 由模式和形态派生出各项行为（是否独立桌面窗口、用不用子窗口承载等） |
| `entry/src/main/ets/pages/Index.ets` | 设置页的模式切换入口（按形态决定显不显示） |

**改这个默认值要保守**：平板分支的默认值只能是「虚拟桌面」，不能默认开多窗口。这是明确的约定，改动前先回看本文。
